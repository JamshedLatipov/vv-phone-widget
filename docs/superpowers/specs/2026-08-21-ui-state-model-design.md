# Модель состояний UI

**Дата:** 2026-08-21
**Статус:** утверждён

## Цель

Свести весь UI софтфона к одному выводимому состоянию и одному месту, где это
состояние меняется.

Сейчас то, что оператор видит, определяется пятью независимыми переменными:
`_preferredMode`, `_isExpanded`, `_currentTab`, `_settingsFromLogin` и `CallState`
сервиса. Первые четыре живут в `MainWindow` и назначаются вручную — `_isExpanded`
присваивается в девяти местах, содержимое окна ставится в двадцати одном. Их
произведение даёт около двух сотен комбинаций, осмысленны из которых единицы, и
ничто в коде не отличает одни от других. Каждый новый экран добавляет ещё один
набор ручных присваиваний, которые надо не забыть.

Rework нижнего меню (`2026-08-21-bottom-nav-design.md`) уже сделал этот ход для
одного контрола: кнопка докладывает нажатие, `MainWindow` решает, куда идти, и сам
же выдаёт контролу состояние. Здесь — то же самое, но для окна целиком.

Второй повод: у активного звонка нет места в модели. Он одновременно полоска
436×132 (при этом `_isExpanded=true`, хотя это не панель), панель с табами, и
подмена таба «Набор». Уйти с экрана звонка можно только через таб, который на
время звонка перестаёт быть набором, — то есть второй линии и ввода адреса
перевода взять негде.

## Границы

Не входит в эту работу:

- **Содержимое экранов.** Что лежит на «Истории», «Задачах», «Наборе» и в
  «Настройках», не меняется. Меняется только то, кто их показывает и когда.
- **Кэш экранов.** Экраны продолжают пересоздаваться на каждом переходе, как
  сейчас; набранный номер и позиция скролла теряются, как теряются и сегодня.
  Решено сознательно: кэш требует явного «экран снова показан» на каждом из
  четырёх табов, и это отдельная работа.
- **Переезд диалогов в панель.** Задача, анкета, скрипты и SMS остаются отдельными
  немодальными окнами. Анкета и скрипты обязаны быть видны одновременно с экраном
  звонка — внутри панели 320×600 это невозможно.
- **Стили, локализация, звук, SIP, бэкенд.** Не затрагиваются.
- **HTTP-баннер.** Это тост поверх всего, живущий по своему таймеру и своей
  геометрии вне `LayoutTransformControl`. В модель состояний не входит и остаётся
  как есть.

## Решения

### Состояние — одна запись

```csharp
public enum Shell { Login, LoginSettings, Collapsed, Panel, Incoming, CallBar }

public enum NavRoute { Dialer, Recents, Tasks, Settings, Call }

public sealed record UiState(
    Shell    Shell,
    NavRoute Route,        // route панели; переживает уход в Collapsed и CallBar
    NavRoute LastNonCall,  // куда падать, когда звонок кончился на Route=Call
    Shell    Home,         // Collapsed | Panel — «дом» оператора
    bool     StatusPopup);
```

Три сегодняшних поля исчезают, потому что становятся выводимыми:

| Было | Стало |
|---|---|
| `_isExpanded` | `Shell != Collapsed` |
| `_settingsFromLogin` | `Shell == LoginSettings` |
| `_preferredMode` | `Home` |
| `_currentTab` | `Route` |

`Shell.LoginSettings` — отдельная поверхность, а не флаг над настройками. Флаг уже
один раз протёк: очищаемый только на тех выходах, о которых кто-то вспомнил, он
позволял панели отвеченного звонка унаследовать режим логина. Поверхность
протечь не может — из неё ведёт ровно один переход.

`CallState` в записи **отсутствует**. Единственный его источник — `SipService`;
редьюсер получает его параметром. Зеркало состояния звонка внутри UI — ровно тот
класс ошибок, который уже стоил DTMF-панели (`3424db8`).

### Редьюсер

```csharp
public static class ShellRouter
{
    public static UiState Reduce(UiState current, UiEvent e, CallState call);
}
```

Чистая функция без ссылок на Avalonia: та же тройка на входе всегда даёт то же
состояние на выходе. Побочные эффекты — `CallAsync`, `Hangup`, `SetStateAsync`,
открытие окон — остаются в `MainWindow`; редьюсер о них не знает.

События:

```csharp
public abstract record UiEvent
{
    public sealed record Started(bool HasCredentials)  : UiEvent;
    public sealed record LoginSucceeded                : UiEvent;
    public sealed record SessionExpired                : UiEvent;
    public sealed record LoginSettingsRequested        : UiEvent;
    public sealed record SettingsSaved                 : UiEvent;
    public sealed record TabPressed(NavTab Tab)        : UiEvent;
    public sealed record ReturnStripPressed            : UiEvent;
    public sealed record ExpandRequested               : UiEvent;
    public sealed record CollapseRequested             : UiEvent;
    public sealed record IncomingCall                  : UiEvent;
    public sealed record IncomingDeclined              : UiEvent;
    public sealed record CallStarted                   : UiEvent;  // ответ или исходящий
    public sealed record CallStateChanged(CallState S) : UiEvent;
    public sealed record StatusPopupToggled(bool Open) : UiEvent;
}
```

### Таблица переходов

Полная. Всё, чего в ней нет, состояние не меняет.

| Событие | Условие | Результат |
|---|---|---|
| `Started` | нет учётных данных | `Login` |
| `Started` | есть | `Collapsed`, `Home=Collapsed`, `Route=LastNonCall=Dialer` |
| `LoginSucceeded` | — | `Collapsed`, `Home=Collapsed`, `Route=LastNonCall=Dialer` |
| `SessionExpired` | `call == Idle` | `Login`; окна-диалоги закрыть |
| `SessionExpired` | звонок жив | состояние не меняется, событие отложено до `CallStateChanged(Idle)` |
| `LoginSettingsRequested` | `Shell == Login` | `LoginSettings` |
| `SettingsSaved` | `Shell == LoginSettings` | `Login` |
| `SettingsSaved` | `Shell == Panel` | без изменений |
| `TabPressed(t)` | `Shell == LoginSettings` | `Login` |
| `TabPressed(t)` | `t == Route` | без изменений |
| `TabPressed(t)` | иначе | `Panel{Route=t, LastNonCall=t}` |
| `ReturnStripPressed` | звонок жив | `Panel{Route=Call}` |
| `ExpandRequested` | `Shell == Collapsed` | `Panel` (route прежний), `Home=Panel` |
| `ExpandRequested` | `Shell == CallBar` | `Panel{Route=Call}`, `Home=Panel` |
| `CollapseRequested` | звонок жив | `CallBar`, `Home=Collapsed` |
| `CollapseRequested` | иначе | `Collapsed`, `Home=Collapsed` |
| `IncomingCall` | `call == Idle` | `Incoming` |
| `IncomingCall` | звонок уже идёт | без изменений |
| `IncomingDeclined` | — | `Home` |
| `CallStarted` | `Home == Panel` | `Panel{Route=Call}` |
| `CallStarted` | `Home == Collapsed` | `CallBar` |
| `CallStateChanged(Idle)` | отложен `SessionExpired` | `Login` |
| `CallStateChanged(Idle)` | `Shell == Panel`, `Route == Call` | `Panel{Route=LastNonCall}` |
| `CallStateChanged(Idle)` | `Shell == Panel`, `Route != Call` | без изменений |
| `CallStateChanged(Idle)` | `Shell == CallBar` | `Collapsed` |
| `CallStateChanged(Idle)` | `Shell == Incoming` | `Home` |
| `CallStateChanged(_)` | прочее | без изменений |
| `StatusPopupToggled(v)` | — | `StatusPopup = v` |

Поверх таблицы действуют три инварианта, которые редьюсер применяет к своему
результату, а не к каждой строке по отдельности:

1. **`Route == Call` допустим только при живом звонке.** Любой результат, в котором
   звонок мёртв, а route — `Call`, приводится к `Route = LastNonCall`. Это снимает
   вопрос «а что, если оператор развернул виджет ровно в тот момент, когда собеседник
   положил трубку» со всех строк сразу.
2. **`LastNonCall` никогда не равен `Call`.** Он обновляется только там, где route
   меняется на не-звонковый, — то есть в единственной строке `TabPressed`.
3. **Любой переход, меняющий `Shell` или `Route`, обнуляет `StatusPopup`.** Это уже
   сегодняшнее поведение (`SetMainContent` зовёт `HideStatusPopup`), но здесь оно
   становится правилом, а не побочным эффектом одного метода.

`NavTab` (четыре слота меню) отображается в `NavRoute` один к одному; пятого слота
для `Call` в меню нет и не будет — попасть на этот route можно только через плашку
возврата, разворот `CallBar` или начало звонка. Именно поэтому `NavRoute` — отдельный
тип, а не расширенный `NavTab`.

Ещё две строки стоит прочитать отдельно.

**`CallStateChanged(Idle)` при `Route != Call`** — конец звонка больше не выбрасывает
оператора с «Задач» или «Истории». Сегодня для этого держится список исключений
(`Login` и `Settings` остаются, остальные — нет), и каждый новый экран требует
решения, в какой половине списка он лежит. Правило «звонок уходит с того экрана,
на который сам и пришёл» не требует списка вовсе.

**`TabPressed(t)` при `t == Route`** — нажатие на подсвеченный таб инертно.
Правило пришло из rework нижнего меню и остаётся: иначе тап по горящим
«Настройкам» уносит несохранённые host, учётные данные, язык и масштаб, а тап по
горящему «Набору» — наполовину набранный номер.

### Что рендерит окно

`MainWindow` перестаёт быть логикой и становится рендерером диффа:

```csharp
private void Apply(UiState prev, UiState next)
```

Четыре шага, в этом порядке:

1. **Геометрия** — чистая функция от `Shell`:

   | `Shell` | Размер (базовый, до `_uiScale`) | Размещение |
   |---|---|---|
   | `Login`, `LoginSettings` | 320×600 | центр рабочей области при входе |
   | `Panel` | 320×600 | якорь по нижне-правому углу |
   | `Collapsed` | 96×96 | якорь по нижне-правому углу |
   | `Incoming`, `CallBar` | 436×132 | якорь по нижне-правому углу |

   Размер изменился — идёт анимация; не изменился — контент меняется без неё.
   Размещение логина по центру перестаёт быть свойством двух методов, которые его
   строят, и становится свойством поверхности.

2. **Контент** — от пары `(Shell, Route)`. Пара изменилась → экран строится заново
   и подписывается. Не изменилась → не трогаем: `Apply` вызывается и на изменение
   одного лишь `StatusPopup`.

3. **Хром** — `ActiveTab`, `SetInCall`, бейджи, видимость плашки возврата.
   `ActiveTab` берётся из `Route`; для `Route=Call` ни один таб не подсвечен, что
   и убирает сегодняшнюю ложь про «Набор».

4. **Оверлей** — `StatusPopup` в `PopupHost`.

Все двадцать одна точка установки содержимого схлопываются в один
`Dispatch(UiEvent)`, который зовёт `Reduce` и передаёт результат в `Apply`.

### Хром панели переезжает в один контрол

Топбар и нижнее меню сегодня продублированы в разметке пяти экранов. Плашка
возврата к звонку потребовала бы шестого дубля — и, что хуже, каждый экран
пришлось бы учить показывать и прятать её.

Вместо этого вводится `PanelShellView`: `TopBarControl` + `CallReturnStrip` +
`ContentControl` + `BottomNavControl`. Экраны становятся чистым содержимым и
теряют свои копии хрома. `Apply` ставит экран внутрь `PanelShellView`, а не в
`Host` напрямую.

Цена честная: правятся пять `.axaml` и их code-behind, включая маржины и `Grid.Row`,
которые сегодня подогнаны под собственный хром каждого экрана (`SettingsView`
компенсирует свой отступ через `Margin="-20,20,-20,-20"`). Это единственная часть
работы с риском визуальной регрессии.

### Плашка возврата к звонку

Живёт в `PanelShellView`, между топбаром и содержимым. Видна ровно тогда, когда

```
call != CallState.Idle   &&   Route != Call
```

`CallState` — это `{ Idle, Ringing, IncomingRinging, Active, OnHold }`. «Звонок жив»
везде в этом документе означает «не `Idle`»: исходящий гудок (`Ringing`) уже даёт
оператору что-то, к чему можно вернуться, а `IncomingRinging` живёт на собственной
поверхности `Incoming`, где панели с плашкой всё равно нет.

Содержит номер (или имя, если `CallInfoService` его знает), таймер разговора и
жест возврата: тап по всей плашке поднимает `ReturnStripPressed`. Таймер тикает от
`SipService.ActiveCallStartedAt`, а не от собственного счётчика, — иначе он
разъедется с таймером на экране звонка.

Из этого следует то, ради чего всё затевалось: во время звонка «Набор» остаётся
набором. Вторая линия и ввод адреса для перевода получают экран, на котором их
можно сделать.

### Окна-диалоги

Пять немодальных окон, каждое под своим `SingleWindowGuard`: задача, анкета,
скрипты, SMS с экрана звонка, SMS из истории.

- Владелец — всегда `MainWindow`.
- **Смена экрана и конец звонка их не закрывают.** Постобработка живёт дольше
  разговора, а недописанный черновик SMS дороже консистентности.
- **Истечение сессии закрывает все.** Их содержимое принадлежит сессии, которой
  больше нет; отправить или сохранить из них уже нечего.
- Свёртка в трей прячет их вместе с главным окном и возвращает вместе с ним.
- Повторная попытка открыть окно того же вида активирует уже открытое. Так
  сегодня и работает; правило записывается, чтобы новые точки входа его не
  нарушали.

Модальность не возвращается ни при каких условиях: `ShowDialog` выключает
владельца, и пока форма висела, оператор не мог ни положить трубку, ни ответить
на следующий вызов.

### Хоткеи и трей

Хоткеи — четыре глобальных (mute, hold, hangup, answer) и четыре оконных
(`Ctrl+M`, `Ctrl+H`, `Esc`, `Enter`) — **не являются событиями навигации**. Они
адресуются звонку через `SipService`, а UI следует за `CallStateChanged`, как за
любым другим изменением состояния звонка. Единственное исключение — `answer` на
`Shell.Incoming`, который поднимает `CallStarted` после успешного `AnswerAsync`.

Видимость окна (трей: Show / Hide / клик по иконке) — **ортогональная ось**, не
входящая в `UiState`. `Hide()` не меняет состояния; `Show()` возвращает окно ровно
в том состоянии, в каком его спрятали, и ничего не перестраивает.

`tel:`/`callto:`/`sip:`-ссылки поднимают `CallStarted` — но только после того, как
`MainWindow` убедился, что `CallState == Idle`. Проверка уже есть и остаётся на
стороне эффекта, а не редьюсера.

### Истечение сессии

Поведение сохраняется целиком, но перестаёт быть отдельным флагом с собственным
путём: `_sessionExpiredPending` становится полем диспетчера, а не состояния, и
отложенный переход выражается двумя строками таблицы выше. Побочные эффекты
(остановка опроса статусов, остановка бейджей, баннер) остаются там же, где сейчас,
в обработчике `BackendAuth.SessionExpired`.

Единственное добавление — закрытие окон-диалогов, описанное выше.

## Тесты

`ShellRouter` — чистая функция, поэтому таблица переходов проверяется целиком, без
окна. `OrbitalSIP.Tests` на xunit; прецеденты того же рода уже есть
(`NavBadgeStateTests`, `TaskListOutcomeTests`, `OpenTaskListTests`).

| Что проверяем | Почему именно это |
|---|---|
| Каждая строка таблицы переходов | Таблица и есть спецификация |
| `TabPressed` на текущем route инертен | Стоило бы несохранённых настроек |
| Конец звонка на `Route != Call` не двигает экран | Сегодняшний список исключений — то, что заменяем |
| Конец звонка на `Route == Call` возвращает на `LastNonCall`, а не на `Home` | Основная новая гарантия |
| `Route=Call` недостижим при `CallState.Idle` | Инвариант 1: иначе экран звонка без звонка |
| `LastNonCall` не становится `Call` ни на одном пути | Инвариант 2: иначе откат после звонка ведёт в звонок |
| Свернуть во время звонка → после звонка `Collapsed`, следующий звонок в `CallBar` | `Home` обязан следовать за жестом, иначе следующий звонок разворачивает панель тому, кто её свернул |
| `SessionExpired` при `call == Idle` даёт `Login` с любого экрана | Отложенный случай диспетчер сводит к этому же: дождавшись `Idle`, он шлёт `SessionExpired` повторно, а не `CallStateChanged` |
| `IncomingCall` при живом звонке не двигает экран | Второй вызов не должен снимать оператора с разговора |
| `ShellGeometry` даёт три размера и две политики размещения | Логин по центру — свойство поверхности |
| Плашка видна ⟺ `звонок жив && Route != Call` | Предикат вынесен в `ShellRouter`, проверяется без UI |

## Порядок работ

1. `Shell`, `NavRoute`, `UiState`, `UiEvent`, `ShellGeometry` + тесты геометрии.
2. `ShellRouter.Reduce` + тесты всей таблицы. Код окна ещё не тронут.
3. `MainWindow`: `Dispatch` и `Apply` рядом с существующими `Show*`, поверхности
   переводятся по одной, начиная с `Collapsed` и `Panel`.
4. `Login`, `LoginSettings`, `Incoming`, `CallBar` — вместе с ними уходят
   `_isExpanded`, `_preferredMode`, `_settingsFromLogin`.
5. `PanelShellView` и вычистка хрома из пяти экранов.
6. `CallReturnStrip` и `Route=Call` как полноценный route.
7. Правила окон-диалогов: закрытие по истечению сессии, скрытие вместе с окном.

Шаги 1–2 не меняют поведения вообще; шаг 6 — единственный, который его добавляет.

## Риски

- **Визуальная регрессия при выносе хрома.** Пять экранов подогнаны под
  собственные копии топбара и меню, включая отрицательные маржины. Смягчение:
  шаг 5 идёт отдельным коммитом на экран, а не одним махом.
- **Анимация и диффы.** Сегодня анимация и смена контента переплетены
  (`_pendingContent`, `CompleteAnimatedContentSwap`, `OverlayHost`). `Apply` обязан
  оставаться корректным, если событие пришло посреди анимации; сегодня это
  разрулено тем, что `ShowLoginAfterSessionExpiry` вручную гасит таймер.
- **Плашка съедает высоту.** 320×600 — не тот бюджет, где 36 px бесплатны.
  Проверить на «Задачах» и «Истории», где список и так упирается в низ.
- **Второй входящий.** Модель говорит «не двигать экран», но что при этом делает
  `SipService`, спецификацией не покрыто и в эту работу не входит.
