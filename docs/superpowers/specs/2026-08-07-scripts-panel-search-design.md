# Панель скриптов: быстрый поиск, кэш и личная статистика

**Дата:** 2026-08-07
**Статус:** утверждён
**Продолжает:** [2026-07-22-scripts-picker-ux-design.md](2026-07-22-scripts-picker-ux-design.md)

## Проблема

Панель скриптов показывает содержимое скрипта корректно (это сделал предыдущий
спек), но найти нужный скрипт долго.

1. **Поиск не ранжирует.** `ApplyFilter` возвращает отфильтрованное дерево:
   совпадение в подсказке весит столько же, сколько совпадение в заголовке, а
   порядок — алфавитный. Число скриптов зависит от клиента и доходит до сотен —
   на таком объёме оператор листает выдачу, пока клиент ждёт.
2. **Каждое открытие — сетевой запрос.** `GetScriptsAsync()` ходит на
   `/api/call-scripts` при каждом показе окна, и до ответа панель пустая.
3. **История не используется.** Оператор, который весь день работает по одной
   кампании, каждый раз ищет один и тот же скрипт заново.
4. **Клавиатуры почти нет.** Из поиска в список стрелками не уйти, `Enter` не
   сохраняет, `Esc` закрывает окно даже когда оператор хотел лишь стереть
   опечатку в поиске.

Оператор понимает, какой скрипт нужен, двумя способами: по контексту звонка и по
словам клиента. Локально виджету доступен только номер и направление звонка —
очередей и кампаний в нём нет, они живут на бэкенде (`../crm_mono`).

## Границы

Меняется только виджет. Бэкенд не трогаем: `/api/call-scripts` и `/api/cdr/log`
остаются как есть. Значит, подсказка по очереди/кампании в этот объём не входит —
из контекста звонка используется только направление.

## Решение

Три независимых куска, каждый со своим файлом и своими тестами:

- `Services/ScriptSearch.cs` — ранжирование выдачи (чистая логика, без UI)
- `Services/ScriptCache.cs` — кэш дерева в памяти и на диске
- `Services/ScriptUsageService.cs` — локальный счётчик использований

`ScriptsDialog` остаётся picker'ом и по-прежнему ничего не знает про резолв
`uniqueId` и `LoggedCallService`.

### Раскладка

Правая панель (детали + комментарий) и футер не меняются. Левая получает два
режима.

```
Поиск ПУСТОЙ                        Поиск НЕПУСТОЙ («верн»)
┌──────────────────────┐            ┌──────────────────────┐
│ [ поиск...         ] │            │ [ верн             ×]│
│ [Все][●Продажи][●…]  │            │ [Все][●Продажи][●…]  │
│                      │            │                      │
│ НЕДАВНИЕ             │            │ ● Возврат товара     │
│  ● Возврат товара    │            │   Продажи › Возврат  │
│  ● Отказ от заказа   │            │ ● Отказ от заказа    │
│                      │            │   Продажи            │
│ ЧАСТЫЕ               │            │   Шаг 2: …вернуть…   │
│  ● Первичный контакт │            │ ● Гарантия           │
│                      │            │   Поддержка          │
│ ВСЕ СКРИПТЫ          │            │                      │
│  ▾ Продажи           │            │ найдено 3            │
│    ● Возврат товара  │            │                      │
│  ▾ Поддержка         │            │                      │
└──────────────────────┘            └──────────────────────┘
```

**Пустой поиск.** Сверху «Недавние» (до 5) и «Частые» (до 5), ниже дерево — как
сегодня. Секции появляются только начиная с трёх записей в истории: на пяти
скриптах они не нужны и панель выглядит как раньше.

**Непустой поиск.** Дерево скрывается, показывается плоский ранжированный
список. Иерархию несёт вторая строка (`Продажи › Возврат`), а не отступы.

**Строка результата.** Точка цвета категории, заголовок с подсветкой совпавшего
фрагмента, серым — путь родителя. Если совпало не в заголовке, добавляется третья
строка со сниппетом (`Шаг 2: …`), чтобы было видно, почему скрипт нашёлся.

Чипы категорий фильтруют оба режима. Под списком — счётчик найденного. Больше 50
результатов — список режется и показывается «показаны 50 из N, уточните запрос».
В поле поиска появляется крестик очистки.

### Ранжирование — `ScriptSearch`

Запрос режется на токены по пробелам. Скрипт проходит, только если **каждый**
токен где-то нашёлся: на сотнях скриптов OR-логика даёт мусорную выдачу. Поиск
регистронезависимый, по подстроке.

Опечатки (fuzzy) не поддерживаются намеренно: ложные совпадения в выдаче стоят
оператору дороже, чем пропуск, а добавить их поверх готового движка можно потом.

Вес считается по лучшему совпадению для каждого токена и суммируется по токенам:

| Где совпало | Вес |
|---|---|
| `Title`, совпадение с начала слова | 100 |
| `Title`, внутри слова | 70 |
| `Description` | 40 |
| `Steps` / `Questions` / `Tips` | 20 |

К счёту добавляются бонусы из `ScriptUsageService`: за частоту (нормализованная,
с потолком — иначе один скрипт залипает в топе навсегда), за свежесть последнего
использования и за совпадение направления звонка с текущим. При равном счёте —
по алфавиту, чтобы порядок выдачи был стабильным между вводами.

Правило «родитель совпал → показать всех его активных детей» в плоском списке не
действует: дети попадают в выдачу самостоятельно, если совпали. В режиме дерева
(пустой поиск) поведение прежнее.

### Кэш — `ScriptCache`

Два уровня: память (живёт, пока запущен виджет) и диск
`%AppData%/OrbitalSIP/scripts-cache.json` (переживает перезапуск).

**Кэш есть.** Дерево рисуется сразу, без «Загрузка…»; запрос уходит в фон.
Пришёл отличающийся ответ — список тихо перестраивается, при этом сохраняются
текст поиска, выбранный скрипт и черновик комментария. Ответ не пришёл (оффлайн,
5xx) — остаёмся на кэше и показываем узкую плашку сверху: «Данные от 14:32 ·
Обновить». Полноэкранную панель ошибки в этом случае не показываем: она стирает
рабочие данные ради сообщения о том, что данные не обновились.

**Кэша нет.** Поведение сегодняшнее: «Загрузка…», при ошибке — панель ошибки и
кнопка «Повторить».

Прочее:

- Ключ кэша — `backendUrl + username`. Сменился оператор или стенд — старый кэш
  не подхватывается.
- Диск считается годным 24 часа. Более старый показывается, но сразу с плашкой
  устаревания. Успешный фоновый ответ всегда перетирает кэш.
- Нечитаемый или битый файл кэша не должен ронять окно: `try/catch`, дальше
  работаем как при пустом кэше.
- `ScriptsResult` получает два поля — `FromCache` и `CachedAt`. По ним диалог
  решает, показывать плашку устаревания и какое время в ней писать; без них
  «данные из кэша» неотличимы от «данные с сервера».

### Статистика — `ScriptUsageService`

Файл `%AppData%/OrbitalSIP/script-usage.json`. Устройство копирует
`LoggedCallService`: `Load()` в конструкторе, `lock` вокруг мутаций, `Save()`
после записи, `Cleanup()` на старте.

Запись: `{ ScriptId, OperatorId, Direction, Count, LastUsedAt }`. Пишется в
`Confirm()` — то есть когда скрипт действительно сохранён, а не когда его открыли
посмотреть.

- «Недавние» — по `LastUsedAt`, «Частые» — по `Count`, без повторов между
  секциями.
- `Direction` пишется потому, что это единственный контекст звонка, доступный
  локально: `ActiveCallView` знает `isOutgoing` уже в конструкторе
  (`ActiveCallView.axaml.cs:60`), `RecentsView` — из `entry.Direction`.
  `ScriptsWindowLauncher.Open` принимает необязательный хинт направления и
  передаёт его в окно. Хинта нет — ранжирование работает по всей статистике.
- `Cleanup()` удаляет записи старше 60 дней и записи чужих операторов, затем
  обрезает файл до 200 самых свежих.
- Скрипт, которого больше нет в дереве (удалён или деактивирован), в секциях не
  показывается.

### Клавиатура

Цель — не отрывать руку от поля поиска: печатаешь, стрелками выбираешь, `Enter`
подтверждаешь.

| Клавиша | Действие |
|---|---|
| ↑ / ↓ | Двигают выделение по списку или по видимым узлам дерева и сразу показывают детали справа. Фокус остаётся в поиске — можно продолжать печатать |
| → / ← | В режиме дерева: раскрыть / схлопнуть узел |
| `Enter` | Сохранить выделенный скрипт и закрыть окно. Ничего не выделено — ничего не делает |
| `Ctrl+Enter` | Сохранить и закрыть из любого места, включая поле комментария |
| `Esc` | Поиск непустой — первый `Esc` чистит поиск, второй закрывает окно |
| `Tab` | Поиск → список → комментарий → «Сохранить» |
| Двойной клик | Сохранить (как сегодня) |

Поведение `Esc` меняется намеренно: сейчас он закрывает окно сразу, и опечатка в
поиске стоит оператору всего окна посреди разговора.

### Новые ключи i18n

`ScriptsRecent`, `ScriptsFrequent`, `ScriptsAllScripts`, `ScriptsFoundCount`,
`ScriptsResultsTruncated`, `ScriptsStaleData`, `Refresh`, `ClearSearch`.

Существующие переиспользуются: `CallScripts`, `SearchScripts`, `AllCategories`,
`Cancel`, `Save`, `Retry`, `ScriptsLoading`, `ScriptsEmpty`, `ScriptsLoadError`.

## Тестирование

Юнит-тестами (xunit, как весь `OrbitalSIP.Tests`) покрываются чистые части:

- `ScriptSearch` — порядок весов, AND по токенам, стабильность сортировки при
  равном счёте, влияние бонусов, обрезка до 50, границы подсветки
- `ScriptCache` — попадание и промах, истечение TTL, смена ключа при смене
  оператора, битый файл не бросает исключение
- `ScriptUsageService` — инкремент счётчика, порядок «недавних» и «частых»,
  отсутствие повторов между секциями, `Cleanup` по возрасту, оператору и
  потолку в 200 записей

UI-часть (два режима панели, клавиатура, плашка устаревания) проверяется вручную.

## Вне объёма

- командная палитра по глобальному хоткею
- привязка скриптов к очереди или кампании (нужен бэкенд)
- отметки пройденных шагов во время разговора
- ресайз окна и запоминание его размера
- перевод диалога на MVVM
- поиск с учётом опечаток (fuzzy)
